The idea: tiers, not a flat grid

Six equal tiles gave the eye no entry point. Here the order encodes priority — what the data is, how active it's been, who's maintaining it, then what's in it.

Recency legends, decluttered

Dropped the color dots — legend order already matches the bar's left-to-right color order, so they were redundant. Labels trimmed to Last 90d, 90d–1y, 1y–2y, 2y+: "Last" stays on the first entry, since without it "90d" alone could read as a range rather than a starting point.

Recency bar palette options

Three ways to color the 90d/1y/2y/2y+ bands, all built from real tokens (Design Atlas olive/blue/yellow, Tailwind gray). Same Activity numbers (7/14/13/66) throughout — only the colors change.

A — live in the panel. Olive fades to gray, with a hue break at the 1-year mark: two olive steps read "still active," two gray steps read "aging out." Clearest single threshold.
B — single-hue ramp. Stays in the olive family through the 1y–2y band, only the final step goes fully neutral. Reads as one continuous fade rather than two states, but the middle two bands sit closer together and are harder to tell apart at a glance.
C — categorical. Each band gets its own hue (olive / blue / yellow / gray). Bands are the easiest to tell apart even at a sliver's width, but it reads as four different categories rather than one metric fading — works against the "same thing, wearing off" story this bar is telling.

Went with A: it keeps the fade metaphor while making the one threshold that matters most — active within a year or not — legible without reading the legend.

Freshness → Activity

Renamed: the headline number here is "600 edits," a lifetime total — that's a volume stat, not a freshness signal, and reading it alone tells you nothing about how current the data is. Only the bar below it says that. "Activity" covers both halves honestly (how much + how recent); "Freshness" only ever promised the second one.

Shape-wise this tier used to be three cumulative rows (% edited within 2y, 1y, 90d — each including the ones below it). Rebuilt as one segmented bar of exclusive bands, same pattern as Community: last 90 days, 90d–1y, 1y–2y, and 2y+ (the stale majority). Same four-color recency language across both tiers now — olive fading to gray means "long since touched," whether it's features or the people editing them.

Headline is now its own number — 600 edits, not 18,340. Edits (changesets) are naturally fewer than features: a single import or bulk edit can touch thousands of elements in one changeset, so changesetsCount is the right source, not dataCount.

Maintenance section, removed

It conflated three unlike things. "Featured" duplicated the title star, so it's gone. "Next check" is fetch-provenance — it moved up next to Fetched. "Following" is a social signal — now a light count by the title.

Context, dropped

Total area and density were the least actionable numbers on the panel — geography trivia, not a trust signal. Removed rather than re-homed; if area/density are still wanted somewhere, they'd fit better on a "details" expandable than in the default view.

Community: one segmented bar

194 mappers split into four exclusive bands by how recently each last edited: last 90 days, 90d–1y, 1y–2y, and 2y+ (the "rest" — legacy contributors who haven't returned). Color fades left to right from active olive to faded gray, so engagement drop-off reads as a gradient rather than a table of numbers. Same visual language as Activity and the Overview composition bar.

Composition: three colors

Points / lines / areas now use three distinct hues (green / blue / amber — categorical, separate from the accent), and every present type keeps a minimum sliver so a handful of areas among 18k points is still visible. The dominant color still reads "almost all points" at a glance.

Most used tags, combinations dropped

Combinations column removed — at two columns wide, its key=value + key=value strings didn't have room to breathe and read as cramped/overflowing. The single Most used tags list counts key presence only, regardless of value — shelter at 35% means 35% of features have a shelter tag at all, whatever its value.

Actions: three tiers, not one stack

Primary — Follow, filled, alone at the top: the one button meant to earn organic use, not competing with anything else for attention. Toolbar — Download and a (not-yet-built) Share icon side by side: this row is where future actions like Embed go, one icon wider each time, instead of one more full-width row taller. Admin — Refresh/Unfeature demoted below a dashed rule with a label: for a regular user this whole block simply isn't rendered, so their view is a complete two-piece design (Follow + toolbar), not "the admin panel minus two buttons."

What's feasible today

  • ready Fetched, Following (saves), Last edited.
  • approx "Next check" — no per-dataset schedule; earliest is lastChecked + 24h, real time depends on the cron queue. Shown as "~Nh", not a promise.
  • ready Most used tags — a single pass over feature properties client-side, counting key presence; cheaper than the dropped combinations pass.
  • ready Share — copies the dataset page URL to the clipboard. Scoped now; trivial to wire up, no new backend needed.
  • ready Activity bar — all four segments are subtractions of fields already computed in dataset-snapshot.ts: 90d = recentActivity.elementsEdited / dataCount, 90d–1y = recentlyUpdatedElementsPercentage minus the 90d share, 1y–2y = (100 - staleElementsPercentage) minus the 1y share, 2y+ = staleElementsPercentage. No new backend work.
  • compute Lines (km) & areas (km²) totals — not computed anywhere yet, but derivable client-side the same way landAreaKm2 already is: sum @turf/length over LineString/MultiLineString features, @turf/area over Polygon/MultiPolygon features. Deterministic, SSR-safe, no backend change.
  • compute Community bar — today the snapshot only keeps editorsCount (all time) and a 90d editor set. The 1y/2y bands need one more pass: track each editor's most-recent edit timestamp (a Map<user, Date> built in the same loop that already builds the editors Set) and bucket by it. Cheap to add, not yet there.

Open questions for you

  • "Following" vs "Save" wording — one concept or two?
  • Overview legend (Points/Lines/Areas): icon-only instead of words? Worth trying during implementation, but three unlabeled glyphs may ask more of a first-time user than three short words do — check with real users before committing either way.
